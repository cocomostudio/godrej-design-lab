# nginx

nginx is the reverse proxy in front of the production boxes. It listens on 80
and forwards to the application behind it — the CMS on 1337, the website on
3000. How many boxes that is, is a question this document cannot answer; see
the closing section.

**This configuration is not yet tracked as files in this repository.** It is
applied by hand on each host and recorded here as the one description of what
those hosts actually run. It belongs in `infra/production/<host>/nginx/`
alongside the PM2 ecosystem files, and should move there when someone next
touches the deployment; `infra/README.md` already describes the proxy as
"planned". Until it moves, this document and the nginx section of
`docs/Operation Manual.md` must be kept saying the same thing — a rebuild that
follows either one should land on the same host.

Every block below is idempotent: re-running it overwrites the file it writes.

## Suppressing the server banner

Godrej's VAPT report flagged that responses disclose the reverse proxy's name
and version. nginx sends `Server: nginx/<version>` on every response it
writes, including its own error pages, and a version number lets an attacker
shop for exploits specific to that build.

`server_tokens off;` removes the version. It goes in the **`http` context**, not
in the individual `server` blocks, so that it covers every server on the box —
including nginx's own stock `default_server` and the error pages nginx generates
before any of our blocks are reached. Files in `conf.d/` are included from
inside `http`, so a drop-in there is an `http`-level directive; the `00-` prefix
just keeps it sorting first when an operator lists the directory.

Apply on **every host that runs nginx** — the same file, unchanged, on each:

```bash
cat <<'EOF' | sudo tee /etc/nginx/conf.d/00-server-tokens.conf
# Suppresses the nginx version in the Server header and in generated error
# pages. http-level rather than per-server, so it also covers the stock
# default_server and nginx's own error responses.
#
# This removes the version but NOT the name: responses still say
# `Server: nginx`. See docs/Nginx.md for why that is where we stopped.
server_tokens off;
EOF
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

`nginx -t` is not optional here. If some earlier hand-edit already set
`server_tokens` in the same `http` block, nginx refuses to start with
`"server_tokens" directive is duplicate` — and a failed reload on a box serving
traffic is worth catching before it happens rather than after.

### What this does and does not remove

| Before | After |
| --- | --- |
| `Server: nginx/<version>` | `Server: nginx` |

The name survives. Stock nginx has no directive that removes or rewrites the
`Server` header — the only ways to do it are the third-party `headers_more`
module (`more_clear_headers Server;`) or patching the source. Amazon Linux
2023's repositories do not carry that module; check before assuming otherwise:

```bash
dnf list --available 'nginx-mod-*'
```

If it is absent, removing the name means running an nginx we build ourselves,
which trades a one-line configuration change for a binary that no longer
updates with the distribution's security patches. That is a bad trade for the
residual risk involved: the version is what makes a banner actionable, and the
version is gone. **This was a deliberate stop, not an oversight.** If Godrej's
IT team asks for the name to go too, it is a conversation about who maintains
the nginx build, not a configuration change.

The application tier discloses nothing of its own: the website's Express server
runs with `x-powered-by` disabled (`apps/frontend-website/server/web/index.ts`)
and the CMS has `strapi::poweredBy` removed from its middleware chain
(`apps/cms/config/middlewares.ts`). Neither Express nor Koa sends a `Server`
header at all, so after this change nginx is the only thing naming itself.

### Verifying

From anywhere that can reach the box:

```bash
curl -sSI http://<host>/ | grep -i '^server:'
```

Expect exactly `Server: nginx`. Also check a path nginx answers itself rather
than proxying, because error pages are generated by nginx and carry the banner
too:

```bash
curl -sSI -H 'Host: no-such-host.invalid' http://<host>/ | grep -i '^server:'
```

## The CMS box

```bash
cat <<'EOF' | sudo tee /etc/nginx/conf.d/cms.conf
server {
  listen 80;
  server_name _;
  client_max_body_size 50M;
  client_body_timeout 600s;
  keepalive_timeout  600s;
  send_timeout       600s;

  location / {
    proxy_pass http://localhost:1337/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
EOF
```

`client_max_body_size 50M` and the three 600-second timeouts are here for the
media library: a large upload that nginx cuts off arrives at Strapi as a
truncated request, not as a clear error.

## The website box

```bash
cat <<'EOF' | sudo tee /etc/nginx/conf.d/frontend.conf
server {
  listen 80;
  server_name _;

  location / {
    proxy_pass http://localhost:3000/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
EOF
```

Port 3000 is `HTTP_SERVER_PORT` in `apps/frontend-website/.env.production`.
Nothing reconciles the two — change one and you change the other by hand.

The security headers on website responses are **not** set here. They are set by
the website's own Express server, so that they apply to static assets as well as
to rendered pages and survive a proxy rebuild. See
`docs/decisions/00001-website-serves-its-own-responses.md`.

## How many hosts is this, actually?

`docs/Operation Manual.md` describes three EC2 instances behind an ALB.
`infra/README.md` describes two machines, a different service account, and no
proxy at all. The two do not agree, and the disagreement is not resolved here.

It is written up at [`infra/topology-discrepancy.md`](../infra/topology-discrepancy.md)
for the project lead to settle. **Apply the banner drop-in to every host that
runs nginx**, whatever that number turns out to be — the command is the same on
each and costs nothing to re-run.
